为什么积分不按「模型倍率」折算？以及本看板多做了什么
  • 官方《积分》文档只说明「消耗量与模型定价和任务复杂度有关」，未公开逐模型的四段积分单价；客户端模型面板显示的 x0.06 / x0.79 等倍率会随活动、峰谷时段变动，不能当计费依据。
  • 因此金额估算走的是官方账单积分 → 套餐单价折算这条可验证的路径，而不是猜倍率。
  • 本看板额外做了一步：用本地逐调用账单做最小二乘，反推每个模型的实测积分单价（积分 / 百万 token，分缓存命中 / 未命中输入 / 输出三段）。多数模型 R²≈1，说明积分确实按四段 token 线性计价，见下表「账单反推积分单价」。
  • 腾讯云公开的「Credits/Million tokens」表属于企业 / 国际 Token Plan 口径，与国内个人版积分反算相差 3–15 倍，本项目不采用。

数据口径与已知局限

1
数据源
会话记录 ~/.workbuddy/projects/**/*.jsonl 中每条带 providerData.rawUsage 的记录 = 一次模型 API 调用；按 providerData.messageId 去重。
2
官方积分
workbuddy.db :: session_usage.credit_json，key 为去掉连字符的 conversationRequestId；有账单时以账单为准，无账单时回退到逐调用 rawUsage.credit 之和。
3
请求树
一次用户请求（conversationRequestId）可能包含几十次 API 调用。下钻层级为：日 → 会话 → 请求 → 单次调用。
4
四段 token
未命中输入 = prompt_cache_miss_tokens；输出 = completion_tokens；缓存命中 = prompt_cache_hit_tokens + cache_read_input_tokens；缓存写入 = prompt_cache_write_tokens + cache_creation_input_tokens。
5
峰谷判定
按单条调用时间戳，工作日北京时间 09:00–12:00、14:00–18:00 为峰时，其余谷时（周末全天谷时）。
6
局限
仅覆盖本地残留的会话日志；被清理 / 未落盘 / 其他设备的会话不在内。厂商牌价是快照，会变动；缓存写入多数厂商不单独收费，按未命中输入同价保守计入。金额均为估算，不是账单。
05 / Access

怎么打开它，数据怎么变新

自动任务只是可选项，不是查看的前提

两种外部打开方式

A
双击 open-snapshot.bat
打开时重新采集一遍，把数据写死进 token-dashboard-latest.html 并唤起浏览器。等价命令 python scripts/run.py --open。不双击就是上次那份快照。
B
双击 start-live.bat（推荐）
启动只监听 127.0.0.1 的本地服务，浏览器打开 http://127.0.0.1:8765/。每次请求检查日志修改时间，源数据变了现场重算；页面每 20 秒自动探测并重载，右下角可手动「重新读取」。/api/data 直接给原始 JSON。
C
定时任务（可选）
每天 09:00 跑一次 run.py --no-prompts 并上传资料库。适合「不在电脑前也想留一份」；缺点是当天中途的数据看不到，且天天上传会在资料库堆一坨快照。本项目默认不创建。
D
多台设备怎么汇总
每台设备跑 python scripts/export.py --device <名字> --out <同步盘>/<名字>.json，把便携包丢进同一个同步盘目录；主设备用 --sources <同步盘目录> 启动，看板自动合并所有设备的记录并按设备拆分。便携包默认不含提示词。
E
两台都在线时自动拉取
另一台设备解压部署包后双击 deploy/START-NODE.bat <密钥> <端口> <设备名>，起一个只读 /api/bundle 节点；主设备填 config/peers.json 后跑 python scripts/serve.py --peers config/peers.json --open。每 60 秒拉一次，对端离线跳过、上线自动补，页面自动重载。同网用局域网 IP，异地用 Tailscale，别映射公网。
!
为什么静态页面不能自己读数据 / 为什么不用云端
浏览器 file:// 沙箱禁止页面 JS 读取 ~/.workbuddy/，所以「写死」和「打开即最新」互斥。WorkBuddy 小程序能看在线状态和对话，靠的是消息通道同步 + 路由回在线桌面端，不同步逐请求四段 token；官网可导出的账号级「积分消耗明细」也只有积分、没有 token 分解。所以跨设备只能靠本地导出汇总。

命令速查

# A 一键快照 + 打开浏览器
python scripts/run.py --open

# B 本地实时服务（打开即最新，Ctrl+C 停止）
python scripts/serve.py --open
python scripts/serve.py --no-prompts --port 8765

# 只采集，输出中间数据
python scripts/collect.py --out output/data.json

# 对外发布用：剔除提示词摘要
python scripts/collect.py --no-prompts --out public/data.json

# 每台设备导出便携包到同步盘（默认不含提示词）
python scripts/export.py --device laptop --out D:/Sync/wb/laptop.json
python scripts/export.py --device desktop --out D:/Sync/wb/desktop.json

# 主设备汇总多设备（--no-local 表示只看同步盘，不掺本机）
python scripts/serve.py --sources D:/Sync/wb --open
python scripts/run.py  --sources D:/Sync/wb --open

# 打包部署到另一台设备（不含本机数据）
python scripts/build_deploy_kit.py

# 主设备自动拉取在线对端（config/peers.json 填地址与密钥）
python scripts/serve.py --peers config/peers.json --open
python scripts/peers.py --config config/peers.json --out output/bundles

# 安装为 WorkBuddy Skill（可选）
python scripts/install.py
Skill 只是让 WorkBuddy Agent 能调用这些脚本，不是浏览器插件；看板本身不依赖它。 数据全程只在本机读取；服务只绑回环地址。上传资料库或对外分享前务必用 --no-prompts。
